# Copilot Instructions

## Style and Conventions
- Follow **PEP8**.
- Use **type hints** where possible.
- Write **clear, maintainable code** with meaningful variable names.

## Project Rules
- All metrics must return a `MetricResult` with:
  - `.tables`: pandas DataFrames with consistent keys
  - `.charts`: Plotly figures
  - `.summary`: short string summary
- All CSV field normalization must go through `Normalizer`.
- Configuration is always read from `metrics.params` in the YAML config.
- `intended_env` and `leak_envs` **must be lists** (no backward compatibility for strings).
- Avoid hardcoding values. Use config-driven parameters whenever possible.

## Expectations
- When asked to generate code:
  - Ensure it integrates with the existing architecture.
  - Keep the metric outputs consistent so they render properly in reports.
- When asked for explanations:
  - Be concise and precise.
- When asked to debug:
  - Point out potential root causes clearly.
  - Suggest minimal, correct fixes.

## Reporting
- Reports are HTML files with:
  - KPI cards (read from special tables)
  - Plotly charts
  - Optional LLM insights (one prompt per metric + summary)

## LLM
- Use **Azure OpenAI client**.
- Keys and endpoint are loaded via `python-dotenv` from `.env`.
- Prompts are stored in `qa_bugs/prompts/` under:
  - `prompts/metric/*.md`
  - `prompts/summary/overall.md`
